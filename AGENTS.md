# ExamOS — project conventions

ExamOS turns a student's own course material into a knowledge map, practice
questions, mastery tracking and a daily study plan. The product question it
answers is **"what should I study today?"** — not "chat with my PDFs".

## Stack

| Concern        | Choice                                              |
| -------------- | --------------------------------------------------- |
| Framework      | Next.js 16 (App Router, Turbopack, React 19)        |
| Language       | TypeScript, `strict`                                 |
| Styling        | Tailwind CSS v4 + shadcn/ui (`radix` base, `nova`)   |
| Database       | PostgreSQL via Prisma 7                              |
| Auth & storage | Supabase Auth + Supabase Storage                     |
| AI             | OpenAI, behind `src/lib/ai/`                         |
| Validation     | Zod v4                                               |
| Tests          | Vitest                                               |

## Next.js 16 specifics that bite

- **There is no `middleware.ts`.** The convention is `src/proxy.ts` exporting
  `proxy()`. It runs on the Node.js runtime; the edge runtime is unavailable.
- Request APIs are async: `await cookies()`, `await headers()`, and `params` /
  `searchParams` are promises.
- Turbopack is the default bundler for both `dev` and `build`.
- Before writing framework code, read the matching page under
  `node_modules/next/dist/docs/01-app/`.

## Prisma 7 specifics that bite

- The client is generated as **TypeScript source** into `src/generated/prisma`
  (gitignored). Run `npx prisma generate` after every schema change; `build` and
  `postinstall` do it for you.
- Connection URLs live in `prisma.config.ts`, **not** in `schema.prisma`.
  `DATABASE_URL` is the pooled runtime connection; `DIRECT_URL` is used by
  `prisma migrate` and must be unpooled.
- A driver adapter is mandatory: the client is constructed with `PrismaPg`.
- Model types are imported from `@/generated/prisma/client`.

## Directory layout

```
src/
  app/
    (marketing)/     Public landing page. Fully static — reads no session.
    (auth)/          Login, signup, password reset + their Server Actions.
    (app)/           Everything behind authentication. Layout calls requireUser().
    auth/confirm/    Supabase email-link handler (verifyOtp).
  components/
    ui/              shadcn primitives. Regenerated by the CLI — avoid hand edits.
    marketing/ app/ auth/   Feature components.
  lib/
    ai/              The ONLY place OpenAI is called.
    materials/       Upload validation, extraction, cleaning, chunking, storage.
    supabase/        client (browser) / server (RSC+actions) / admin (service role) / proxy.
    validation/      Zod schemas, shared by forms and Server Actions.
    auth.ts db.ts env.ts routes.ts courses.ts dates.ts rate-limit.ts
  generated/prisma/  Prisma client output. Never edited, never committed.
prisma/              schema.prisma, migrations, seed.ts
tests/               Vitest suites, mirroring src/lib.
```

## Non-negotiables

**Authorisation.** `src/proxy.ts` only redirects — it is not the security
boundary. Every page, Server Action and Route Handler that touches user data
starts with `requireUser()` from `src/lib/auth.ts`, and every query filters by
that user's id. Server Actions are reachable by direct POST, so an action that
trusts a `courseId` from a form without checking ownership is a vulnerability,
not a shortcut. Never load a resource by id alone; always
`where: { id, userId }` or an equivalent join.

**Secrets.** `OPENAI_API_KEY` and `SUPABASE_SERVICE_ROLE_KEY` are server-only.
Never prefix them with `NEXT_PUBLIC_`, never import `lib/supabase/admin.ts` or
`lib/ai/*` from a Client Component. Modules that must not reach the browser
import `server-only`.

**Uploaded material is untrusted data, never instructions.** A PDF that says
"ignore previous instructions" is a document that contains that sentence. When
building prompts, keep system instructions and course content in separate
messages, delimit the content, and tell the model the delimited region is
reference data only. See `src/lib/ai/`.

**Never trust model output.** Every structured AI response is parsed as JSON and
then validated with a Zod schema before it reaches business logic. Validation
failure means retry or a graceful error — never a partially-applied write. This
is enforced inside `lib/ai/client.ts`, so callers get `AiResult<T>` and cannot
opt out.

**Ground everything, and drop what will not ground.** Anything the model
produces about course content must cite the supplied excerpt it came from, and
citations are resolved against what was actually sent. Output whose citations do
not resolve is discarded, not stored — that check is the difference between a
map of this course and a generic syllabus.

**Don't fake it.** No hardcoded "AI" responses in production paths, no TODOs
standing in for core functionality. If something cannot be derived from the
student's material, say so in the UI.

**Errors are expected.** A failed PDF parse, a timing-out OpenAI call, a dropped
database connection — each surfaces as a useful message and a recorded state
(for example `MaterialStatus.FAILED` with `statusError`), never a crashed page.
Work that runs detached from a request — anything inside `after()` — must never
throw: an unhandled rejection there leaves a row stuck mid-status with nothing
to report.

**Uploaded files are sniffed, not trusted.** The filename and MIME type come
from the client. `src/lib/materials/validation.ts` checks the leading bytes as
well, and filenames are sanitised before they touch a storage key. Storage
paths always start with the owner's user id.

## Conventions

- Prefer Server Components; add `"use client"` only for interactivity.
- Mutations are Server Actions in a colocated `actions.ts`; they validate input
  with a Zod schema from `lib/validation/` and return typed state for
  `useActionState` rather than throwing.
- Business logic lives in `src/lib/*` as pure, testable functions. Mastery,
  readiness and planning must be callable without a database or network.
- Strong typing. `any` needs a comment justifying it.
- Comments explain *why*. Skip the ones that restate the code.
- Tailwind: use the semantic tokens (`bg-card`, `text-muted-foreground`) and the
  ExamOS additions `--color-brand`, `--color-weak`, `--color-moderate`,
  `--color-strong` rather than raw palette colours, so dark mode keeps working.

## Commands

```bash
npm run dev         # start the dev server
npm run build       # prisma generate + next build
npm run typecheck   # tsc --noEmit
npm run lint        # eslint
npm test            # vitest run
npm run db:migrate  # prisma migrate dev
npm run db:seed     # demo data (development only)
```

## Definition of done for a change

`npm run typecheck`, `npm run lint` and `npm test` all pass, and the feature has
tests. A feature is not finished until its tests pass.
